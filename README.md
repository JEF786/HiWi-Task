This repository contains a partial implementation of a pipeline for generating semantic 3D scene graphs from egocentric RGB-D sequences , enriched with structural and topological priors from Industry Foundation Classes (IFC) data.  This project was developed for the Research Assistant (HiWi) Challenge, prioritizing architectural design, scientific documentation, and analytical methodology over a fully optimized production system.  ObjectiveConstructing actionable spatial representations is a core challenge in industrial robotics and spatial computing. While visual-only scene graph generation suffers from occlusions, limited sensor range, and semantic ambiguity , industrial environments often provide rich Digital Twins or Building Information Models (BIM).  The objective of this pipeline is to dynamically generate a visual 3D scene graph from RGB-D data and fuse it with a static architectural prior graph extracted from an .ifc file, utilizing geometric inclusion logic to establish hierarchical relationships between objects and spaces.  Key Components & Methodology1. IFC Data Parsing and Prior Extraction (Task B)Using IfcOpenShell, the pipeline programmatically parses the .ifc file to extract core building entities, including IfcWall, IfcSlab (floors), and IfcSpace. These entities are structured into a NetworkX prior knowledge graph, defining static topological relationships (e.g., adjacent rooms, boundaries) before any visual processing occurs.  2. Visual Point Cloud Processing (Task A)Egocentric RGB-D sequences are mapped to pre-computed 3D point clouds. The pipeline loads the camera trajectories (already aligned to the global IFC coordinate system) and the camera intrinsics matrix extracted from camera_info.json. The point clouds are then voxel-downsampled and statistically filtered to remove noise and outliers.  3. Feature Extraction & Visual Scene Graph GenerationGeometric features are extracted from the processed point clouds:Normal Estimation: Computes local surface orientations using a Hybrid KDTree search ($radius=0.1$, $max\_nn=30$).FPFH (Fast Point Feature Histograms): Generates 33-dimensional descriptors capturing local geometric context ($radius=0.25$, $max\_nn=100$).Currently, the pipeline uses a simplified DBSCAN clustering algorithm on the spatial coordinates to detect "objects." The centroids of these clusters form the nodes ($V_{obj}$) of the visual scene graph, with edges ($E_{rel}$) defined by proximity heuristics.  4. Multimodal Graph FusionThe final stage merges the Visual Graph and the IFC Prior Graph. The pipeline establishes bipartite hierarchical edges (Room -> Object) using geometric inclusion logic.  (Note: Currently, this logic relies on a placeholder distance calculation from the centroid. Critical Analysis & Failure ModesAs per the challenge requirements, a critical evaluation of the current pipeline and potential failure modes is outlined below.  Current LimitationsPlaceholder Geometric Inclusion: In the graph fusion phase, the relationship between an object and a room is currently approximated using the distance to the room's centroid. Ideal Implementation: This should be replaced with a Point-in-Polygon (Ray Casting) algorithm or a direct intersection check between the object's 3D centroid and the bounding box/mesh extracted from the IfcSpace geometry.  Object Detection: The pipeline utilizes simple DBSCAN clustering on spatial coordinates to identify objects. In a dense environment, this will group distinct adjacent items together. Ideal Implementation: Integration of state-of-the-art vision models (e.g., zero-shot segmentation like ConceptGraphs or PIX2Graph).  Geometry Extraction: The get_geometry function currently returns placeholder bounding boxes. Full ifcopenshell.geom processing is required to extract accurate mesh data.  Expected Real-World Failure ModesCoordinate Drift: The provided dataset assumes camera trajectories are perfectly aligned to the global IFC coordinate system. In a real-world scenario, SLAM drift would cause severe misalignment, breaking the geometric inclusion logic. Mitigation requires real-time ICP registration against the IFC prior.  Dynamic Environments: IFC models are inherently static architectural priors. Visual observations will capture dynamic objects (people, temporary machinery, moved furniture) that do not exist in the BIM. This creates an ontology conflict between the two graphs that must be resolved with temporal confidence weighting.  Missing Connective Portals: The current implementation extracts spaces but does not yet extract connective portals (e.g., IfcDoor). Adding portal extraction is critical for defining adjacency relationships and navigable paths in the final graph.
